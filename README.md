# fake-wx-account

基于 [CowAgent](https://github.com/zhayujie/CowAgent) 的 Windows 微信桌面 Agent。项目把微信消息接收、自动回复队列、模型与工具调用、界面发送连接起来，并提供本地 Web 控制台。

适配目标为微信 **4.1.9.30**；本机开发环境为 **Python 3.13.11 x64 / Conda `cowagent-wechat`**。微信通道只提供 `db_uia`：本地数据库负责消息接收和查询，UIA 负责发送与必要的附件操作。

## 微信后端与能力

| 能力 | 当前行为 |
| --- | --- |
| 实时消息来源 | 本机加密数据库，默认每 1 秒检查变化 |
| 普通接收 | 不切换聊天窗口、不激活微信、不执行 OCR |
| 群发送者、方向与 @ | 解析数据库原生身份与消息元数据 |
| 回复上下文 | 实时消息附带同一会话的原生上文；明确引用只追溯一层 |
| 联系人检索 | 按昵称、备注、微信号等检索，返回稳定会话 ID |
| 历史查询 | 按稳定 ID 查库；省略 ID 时被动读取当前界面标题 |
| 附件与引用 | 独立文件及明确的媒体引用，验证唯一关联后按需 UIA 物化；独立图片/分享卡片只观察 |
| 消息发送 | 通过授权和发送门禁后绑定 UIA 目标，逐段提交并验证出站气泡 |

数据库是唯一实时接收来源；UIA 不产生入站事件。数据库故障时保留游标并重试，暂停新事件交付，没有 UIA 接收后备。发送与必要的附件物化可以激活或切换微信；普通接收、授权和原生消息复核保持被动。旧 `desktop_backend="uia"` 配置已不支持。

## 快速运行

在项目根目录使用 PowerShell。所有 Python 命令必须显式使用本项目解释器，首次执行先确认路径：

```powershell
D:\Miniconda\envs\cowagent-wechat\python.exe -c "import sys; print(sys.executable)"
D:\Miniconda\envs\cowagent-wechat\python.exe -m pip install -r .\requirements-windows.txt
```

输出应为 `D:\Miniconda\envs\cowagent-wechat\python.exe`。环境不存在时，用 `D:\Miniconda\Scripts\conda.exe env list` 检查；其他工作站应使用自己 `cowagent-wechat` 环境的绝对解释器路径。

仅在根配置文件不存在时复制模板，随后配置模型、Agent 和通道：

```powershell
if (-not (Test-Path -LiteralPath .\config.json)) {
    Copy-Item .\config-template.json .\config.json
}
```

根 `config.json` 通过下列通用项启用 Web 和桌面微信：

```json
{
  "channel_type": "web,wechat_desktop"
}
```

保持微信已登录，并按下一节设置通道行为。项目管理命令为：

```powershell
.\cow.ps1 start
.\cow.ps1 status
.\cow.ps1 stop
.\cow.ps1 restart
```

启动在当前终端前台运行，默认控制台地址为 <http://127.0.0.1:9899/chat>。也可直接执行：

```powershell
D:\Miniconda\envs\cowagent-wechat\python.exe .\app.py
```

`cow.ps1` 的位置参数为 `start`、`status`、`stop`、`restart`，从 PATH 中的 Conda 查找 `cowagent-wechat` 环境；端口检查使用 9899。修改微信 `config.py` 后需重启整个 `app.py` 进程，网页重连或单独重建通道不会重新加载已经导入的配置模块。

## 配置归属与当前行为

| 配置层 | 唯一来源 | 内容 |
| --- | --- | --- |
| 全局 / Agent | `config.json`；字段模板为 `config-template.json` | 模型、厂商、Agent 工作区、通道启用、Web、通用工具与技能 |
| 微信通道 | [channel/wechat_desktop/config.py](channel/wechat_desktop/config.py) 的 `DEFAULT_CONFIG` | 后端、数据库路径、白名单、群触发、影子模式、节拍、限流、引用和通知策略 |
| 厂商密钥 | `~/.cow/.env` | 先加载环境变量，再按对应能力读取；配置字段仅作可选回退 |

根 JSON 不放 `wechat_desktop` 段或微信业务键。根 `config.py` 负责加载通用配置，不维护微信业务默认值。真实 API Key、微信数据库密钥和聊天内容不进入仓库。

当前仓库的通道默认值如下，首次联调前应明确选择发送范围：

| 字段 | 当前值 | 行为 |
| --- | --- | --- |
| `desktop_backend` | `"db_uia"` | 使用数据库接收，发送仍通过 UIA |
| `shadow_mode` | `False` | 允许正式发送 |
| `auto_reply_private_all` | `True` | 全部私聊通过发送范围检查 |
| `auto_reply_groups_all` | `True` | 全部群通过发送范围检查，群白名单不限制范围 |
| `group_reply_mode` | `"at_only"` | 群消息仍需满足 @ 触发 |
| `db_poll_interval_seconds` | `1.0` | 数据库模式轮询间隔 |

群白名单已包含“816吃喝玩乐群”。若希望仅名单中的群允许发送，将 `auto_reply_groups_all` 改为 `False`；黑名单的优先级高于全部放行与白名单。

以下是**首次受控验证的配置示例**，写入通道 `DEFAULT_CONFIG`，按需要保留其他现有名单：

```python
"desktop_backend": "db_uia",
"shadow_mode": True,
"auto_reply_private_all": False,
"auto_reply_groups_all": False,
"auto_reply_contacts": [],
"auto_reply_groups": ["816吃喝玩乐群"],
"group_reply_mode": "at_only",
"db_data_dir": "",
"db_account": "",
"db_poll_interval_seconds": 1.0,
"db_cache_dir": "",
```

发送白名单与影子模式主要在发送阶段检查；非名单消息仍可能被落账、解析或送入 Agent。会话/发送者黑名单和群触发规则则在扫描路由前过滤。`shadow_mode=True` 禁止发送，正式通道仍可能运行 Agent 或必要附件物化；数据库专用影子诊断会跳过 Agent 和附件流程。

## 自动回复流程

```mermaid
flowchart TD
    O["后端观察新消息"] --> L["接收事务：去重、落账与保存来源游标"]
    L --> F["来源、历史阶段、黑名单与群触发过滤"]
    F --> C{"控制命令？"}
    C -->|是| K["引导或取消当前 Agent"]
    C -->|否| H["私聊聚合与附件路由"]
    H --> Q["全局 FIFO"]
    Q --> E["队首按需物化、复核来源并执行 Agent"]
    E --> N["可选工具进度通知与最终回复"]
    N --> V["发送范围、令牌、暂停、限流及目标验证"]
    V --> J["持久化发送前日志"]
    J --> I["UIA 分段提交与出站验证"]
    I --> Z["记录结果、审计与任务终态"]
```

1. **观察与可靠接收。** 数据库后端生成来源批次，将来源去重、事件、过滤记录、历史和各来源游标一起提交，成功后才 ACK 批次。存储失败会整批重交付；已落账的重复消息不再次路由，没有 UIA 快照单事件接收旁路。
2. **决定是否回复。** 数据库系统消息和出站消息只保存来源过滤记录，出站过滤不依赖 UIA 回声抑制。历史基线、离线补读默认不回复；会话或发送者黑名单、来源类型和原生 @ 等群触发不满足时结束路由。实时事件从同一数据库批次快照取得同会话上文，不重读 UI；明确引用只携带一层引用内容。
3. **聚合与附件准备。** 私聊在回复与物化闲置时可开启滑动聚合窗口，默认静默等待 500–1200 毫秒，最长 4000 毫秒；群聊直接提交。独立图片和分享卡片只记录身份；独立文件在唯一关联验证通过后按需缓存，不自动回复。明确的图片、文件引用、缺少链接的分享引用，以及回查后仍缺少内容的文字或未识别应用引用才按需进入 UIA 物化；文字不会隐式继承此前未引用的附件。已有完整引用文字或分享 URL 时，无需定位气泡或切换微信窗口。
4. **进入 FIFO。** 回复按实际入队顺序追加，由单消费者处理。已排队或正在执行的任务不会被新消息替换。引用附件的实际定位与物化可延迟到队首；该顺序不等于所有会话的原生时间戳全局排序。
5. **运行 Agent。** 通过 Bridge 构建当前会话上下文，模型可调用工具、技能、记忆与知识库。当前文本或一层引用含有 HTTP/HTTPS 链接，且提问需要链接内容时，提示词要求先通过 `analyze-url` 技能或通用工具读取实际内容再回复：静态网页可用 `web_fetch`，动态网页和第三方分享可用 `browser` 导航、快照或正文读取；文件链接走下载与文件解析流程。已有可信页面正文不重复读取，候选历史中的无关链接不自动打开。真正开始调用可见工具/技能时可发进度提示，默认每个回复周期一次；内部工具可静默。引用只追溯一层。
6. **验证并发送。** 最终回复和进度提示都检查队列令牌、停止/暂停、影子模式、黑白名单及额度。按实际气泡数预留配额并写发送前日志，再校验目标、通过 UIA 提交。每个 UI 段保留取消检查；拟人化节拍在 UI 租约之外等待。
7. **收尾与恢复。** 记录已提交/已验证分段、审计和终态。默认回复周期为 180 秒，超时令牌失效并取消 Agent，迟到结果拒绝发送。`partial`、`uncertain` 和 `unverified` 不自动重发；进程重启将旧未完成任务收尾为 `interrupted` 或 `uncertain`，不恢复自动回复队列。

`/cancel` 和 `/steer <指令>` 绕过聚合、附件物化与 FIFO，直接取消或引导当前 Agent，但仍需通过来源、黑名单和群触发检查。

### 引用消息的回复流程

使用时先在微信中引用目标文字、图片、文件或分享卡片，再输入问题，例如“总结这篇内容”或“这个文件说明了什么”。引用消息仍需通过普通消息的黑白名单、群触发、暂停和影子模式等门禁。未明确引用附件而要求读取“这张图/这个文件”时，通道会提示先引用目标，避免读取错附件。

回复只使用**直接引用的一层资料和当前问题**，不混入其他会话上文、同批前序消息或被引用消息的嵌套引用。通过工具取得的该引用网页正文也属于这一层资料；群聊保留当前发送者、引用发送者及原生 @ 语义，提示词移除对机器人的 @ 提及、保留其他成员的 @，出现人名本身不代表要求该成员回应。

```mermaid
flowchart TD
    R["数据库接收引用消息，去重落账并通过回复策略"] --> D["同账号、同会话按 svrid 回查唯一原消息"]
    D --> Q["保存一层引用，进入回复 FIFO"]
    Q --> T{"队首是否需要微信界面读取？"}
    T -->|完整文字或已有 URL| V["投递前复核当前消息与已有原文证据"]
    T -->|附件或仍缺原文、链接| U["严格关联后按需 UIA 物化"]
    U --> V
    V -->|来源失效| X["停止任务，不读取旧链接或发送旧回复"]
    V -->|来源有效| A["Agent 获取引用资料与当前问题"]
    A --> K{"资料类型"}
    K -->|文字| M["结合当前问题生成回复"]
    K -->|可读取的图片或文件| F["vision 或适配文件工具读取"]
    K -->|网页或文件链接| B["analyze-url 与 browser、web_fetch 等通用工具"]
    K -->|资料不可读| E["说明读取限制，不猜测内容"]
    F --> M
    B --> M
    E --> M
    M --> S["发送前复核、UIA 提交、记录回执与终态"]
```

1. **解析与回查原文。** 数据库解析当前问题及内嵌引用，优先按原生 `svrid` 在当前账号、同一会话的全部分片查找唯一原消息，补全正文、文件名或分享 URL。重复 ID、类型/发送者冲突、未来消息等情况不猜测；保留内嵌预览供必要的 UIA 关联。回查不推进实时接收游标，也不创建额外回复任务。
2. **队首按需取得资料。** 完整文字或已有 URL 直接进入 Agent 准备流程；图片、文件、缺少分享链接，以及仍缺内容的文字或未识别应用引用，在 FIFO 队首验证账号、窗口、会话、RuntimeId 和数据库/UIA 序列后才操作微信。必要的界面操作可能激活微信，普通数据库接收与原文回查不需要前台或 OCR。
3. **投递前再次校验。** 当前消息和已回查原文的账号、分片、主键、世代、内容摘要必须仍有效；排队期间的删除、改写或库替换会使任务停止。普通聚合任务也复核前序来源，将失效内容从历史剔除，保留账本与生命周期记录。
4. **读取后回答。** 提示词要求图片调用 `vision`、文件调用适配工具或技能；当前文字或直接引用中的链接若与提问相关，先用 `read` 读取 [analyze-url 技能](skills/analyze-url/SKILL.md)，再按技能调用工具，技能不可用时直接使用 `browser` 或 `web_fetch`。第三方分享或动态页面优先浏览器，静态页面可用 WebFetch，文件链接按文件类型下载解析。保留完整查询参数、复用已有实际正文，同一链接不重复读取，无关历史链接、装饰链接或纯链接举例可跳过。
5. **复核并发送。** Agent 根据引用资料回应当前问题，工具进度通知与最终回复都经过发送门禁和来源复核，再使用现有 UIA 发送流程；成功、未验证或不确定结果按账本规则收尾，不自动重发。

| 引用类型 | 当前读取方式 | 后续处理 |
| --- | --- | --- |
| 文字 | 内嵌引用与数据库原文回查 | 已有完整文字直接给 Agent；引用自带内容仍缺失且能安全关联时按需 UIA 定位 |
| 图片 | 数据库提供类型与原生身份，UIA 打开已验证引用的查看器 | 保存图片后要求调用 `vision` |
| 文件 | 数据库补齐原文件元数据，UIA 定位原文并取得已验证本地文件 | 使用对应文件工具或技能解析 |
| 分享卡片、文字链接 | 已有 URL 交给 `analyze-url` / `browser` / `web_fetch` | 读取真实页面或文件内容；缺少分享 URL 时才按需使用微信 UIA |
| 未识别的应用消息 | 先数据库回查；仍未识别且关联可靠时用 UIA 定位原文重新识别 | 失败明确保留不可读状态；已知语音、视频等不会被冒充成文字或文件 |

**无法取得资料时：** 数据库找不到唯一原文会保留内嵌引用；仍缺少资料时，只有预览及 UIA 身份关联可靠才定位备用。图片或文件不可读时向用户说明无法读取；已知语音、视频等保留明确类型，不冒充文字或文件。网页只返回标题、加载提示、登录页或验证码时不视为已读正文，按技能进行有界尝试后说明限制。当前消息或已绑定原文来源失效时停止任务，不继续调用链接工具或发送旧回复。

例如，引用第三方分享卡片后询问“这篇内容可靠吗？”，数据库若已提供 URL，则无需点击微信卡片：Agent 先通过通用浏览器/网页工具取得实际正文，再结合问题回答；访问受限时说明本次无法读取，不能只根据卡片标题推断内容。

旧 UIA 接收驱动、任务栏钩子、按文件名或前缀猜测引用附件的缓存、物化层网页预取已移除。

## 微信本地数据库：何时解密

### 读取范围与账号绑定

自动发现当前账号 `xwechat_files/.../db_storage/` 下的以下库：

| 数据库 | 用途 |
| --- | --- |
| `contact.db` | 联系人、群聊名称及稳定会话身份映射 |
| `message_<数字>.db` | 消息正文、方向、发送者、@、一层引用和历史 |
| `session.db` | 辅助确认启动未读数量与首条未读边界 |

当前自动发现不接入 `sns.db`、朋友圈或媒体文件解密。数据库只覆盖已经同步到本机的消息，不能代表完整服务端历史。

空 `db_data_dir` 自动定位本机数据目录；空 `db_account` 只在能唯一认证当前登录账号时使用。多账号无法唯一确定时返回明确错误，应指定目录与账号。绑定账号在运行期间固定；同账号重登录会重新建立读取器，不同账号则暂停并要求重新绑定。

### 操作与解密时机

`db_uia` 的构造只建立来源和绑定对象。**第一次实际需要数据库数据时**才创建读取器；正常启动后，首轮数据库观察会触发这一过程。

| 操作 | 数据库行为 | UIA 行为 | 是否推进实时接收游标 |
| --- | --- | --- | --- |
| `db_uia` 首次观察 | 认证账号、获取密钥、首次刷新全量解密 | 不初始化 UIA 网关 | 初始化固定基线；收到批次后随接收事务提交 |
| 后续数据库轮询 | 检查变化，按需刷新快照和分页 | 无需窗口切换或 OCR | 仅随成功提交的接收批次推进 |
| 联系人检索 | 必要时初始化，刷新联系人快照 | 无需 UIA | 否 |
| 按稳定 ID 查询历史 | 刷新快照，再查询指定会话 | 无需 UIA | 否 |
| 引用原文回查 | 在同账号、同会话全部消息分片按原生 ID 唯一查询，保留原文校验证据 | 完整文字或已有 URL 无需 UIA；附件或缺失原文按需另行物化 | 否 |
| 查询当前会话历史 | 刷新快照，再查询对应会话 | 被动读取当前标题与账号，唯一映射到数据库 ID；不激活窗口或打开资料弹窗 | 否 |
| `db_uia` 发送授权与原生消息复核 | 刷新数据库快照，解析可信身份或复核原生消息 | 无需 UIA | 否 |
| `db_uia` 实际发送 | 复核数据库身份与账号生命周期 | 通过发送门禁后绑定窗口、账号、RuntimeId、标题与选中状态，再执行发送 | 否 |
| 必要的附件物化 | 复核原生消息，查询同会话最近最多 50 条用于关联 | 按需定位会话，验证底部与最多 20 条可见消息，再操作唯一目标 | 否 |
| 数据库诊断脚本 | 独立初始化与解密 | 只有指定 `--benchmark-uia` 才读取 UIA 历史作对比 | 独立影子账本，不改业务游标 |

联系人和历史查询不投递入站事件、不触发自动回复，也不将查询结果写入业务会话历史。它们可以刷新解密快照，但不会 ACK 实时消息。

### 密钥与快照的生命周期

1. **初始化账号与密钥。** 只读扫描已登录微信进程中的候选密钥，以数据库首页面 HMAC 认证账号，并取得各库的有效密钥。逐库密钥通过 Windows DPAPI 保存；新账号生命周期仍需认证进程与账号，密钥缓存不免除这一步。
2. **首次全量解密。** 校验主库每页 HMAC，使用 AES 解密，合并通过校验且已提交的 WAL，生成可只读查询的 SQLite 明文快照，并进行结构与完整性检查。正文压缩数据使用 `zstandard` 解析。
3. **空闲轮询。** 检查主库、WAL 和共享内存中的状态。无变化时不重新解密、不重建缓存，也不执行 OCR；正常轮询不重复全进程内存扫描。
4. **WAL 增量。** 同一 WAL 世代只处理新增有效帧，校验头/帧校验和、salt、页 HMAC 和 `-shm` 提交边界。未提交事务不对外发布；已提交页应用到私有快照。
5. **需要重建。** checkpoint 将 WAL 页面回写主库、WAL 重置/截断、数据库替换或读取器重建时，重新建立完整快照。每个读取器使用独立缓存文件，**项目进程重启后首次读取仍会全量解密**。
6. **刷新失败。** 保留最后验证成功的副本，标记陈旧并暂停新事件交付，游标不前进。恢复后继续重试；库来源代次异常、账号变化或密钥错误会明确报告。

刷新快照时按 SQLite 的 WAL 锁协议获取共享锁，以避开提交/checkpoint 交错；全量重建时持锁时间随库规模增加，锁忙则重试。此过程不写微信进程内存或原始数据库。

### 三类本地数据

| 数据 | 默认位置 | 作用与保留 |
| --- | --- | --- |
| 微信原始库 | 微信账号的 `db_storage/` | 微信自身维护的加密库，仅只读访问 |
| 解密缓存与密钥 | `<agent_workspace>/wechat_desktop_db/<account_id>/` | `snapshots/` 保存私有明文副本，正常关闭删除；`keys/` 保存 DPAPI 加密密钥 |
| 业务账本 | `<agent_workspace>/wechat_desktop.sqlite3` | 保存接收记录、历史、过滤、来源游标、任务与发送日志，跨进程恢复接收状态 |

`db_cache_dir` 可覆盖缓存根目录。缓存按账号隔离，Windows ACL 限当前用户与系统访问。**DPAPI 加密的是密钥；解密快照和账本包含聊天明文。** 更换 Windows 用户或机器后需要重新获取密钥。

每个来源流按账号、分片、消息表独立保存游标；消息身份使用原生主键组合，显示名、正文和屏幕坐标不参与数据库消息去重。首次启动固定历史高水位；重启补读只补账本和历史，只有能证明启动未读边界时才应用启动未读回复配置。

## 查询历史、发送绑定与附件边界

Agent 可通过 `wechat_desktop` 检索联系人：

```json
{"action": "search_contacts", "query": "816吃喝玩乐群", "limit": 20}
```

再将返回的原始 `conversation_id` 交给 `wechat_history`：

```json
{"conversation_id": "使用检索返回的稳定会话ID", "limit": 20}
```

省略 ID 时仍表示查询当前打开会话；这一步只被动读取当前界面身份，不激活或切换会话。默认 20 条，上限 50 条；数据库结果包含方向、发送者、原生时间、消息 ID 和来源。不能唯一映射当前会话时返回明确错误，不猜测其他目标。

数据库会话 ID 本身不等于已验证的发送目标。`binding.py` 将其绑定到实际窗口进程、账号与会话 RuntimeId；同名歧义、账号不一致或失效绑定会拒绝发送。界面未提供对方原生身份时明确记录为 `display_name` 验证。每段发送都会复核，关闭或重登录后旧发送调用不能在恢复时继续提交。

数据库接收不需要 OCR，也没有启动 OCR 预热。发送前后使用独立的 UIA 气泡快照，不截图或加载 OCR 模型；只在正文或头像子控件提供明确位置证据时判定方向，证据不足保留 `unknown`，无法确认的新出站气泡记为 `unverified`，不自动重发。显式 UIA 历史诊断和分享卡片复制链接菜单的后备识别可按需使用 OCR。

发送按钮已经尝试执行后，即使输入框仍报告旧值、气泡方向未知，也不能据此再次按 Enter；结果保留为 `uncertain` 或其他未确认状态，不自动重发。原生消息复核包含完整正文及引用/分享结构，物化后的本地路径不替代原生证据。

数据库轮询、发送授权预检查和原生消息复核不会激活微信；账号检查只读当前界面可见信息，不点击头像补全资料。真正执行发送时仍会恢复并激活窗口，目标定位失败也可能已经激活；工具进度和失败通知同样属于发送。

`uia/materializer.py` 保留一层原文定位、图片查看器、文件下载，以及缺少链接时的分享卡片 URL/内置浏览器正文获取。已有链接由 Agent 的通用技能和工具读取，物化层不预取网页。独立图片/分享卡片仍只观察。媒体文件数据库解密与朋友圈未接入。

附件操作必须先证明原生消息与界面目标唯一对应：`ScrollPattern` 能确认可见聊天处于底部；数据库最近最多 50 条与 UIA 最多 20 条形成唯一的尾部匹配，且至少有两种不同的非空类型/内容锚点；目标自身的类型与内容外观在两端都唯一，并有唯一 RuntimeId。引用还需核验正文和已知发送者。进入物化前重新检查账号、窗口、会话 RuntimeId、原生行和两端序列；缺少证据或序列变化时标记 `attachment_identity_unavailable` 并拒绝附件点击。原文定位会改变可见序列，后续界面操作继续核验来源、账号、窗口、当前会话及目标控件。该关联方案已加入替身回归，真实微信 `ScrollPattern` 的覆盖仍待验收，不能保证所有附件都可获取。

数据库附件获取不按文件名、大小或修改时间跨账号搜索缓存；只使用已验证气泡的复制路径或下载/另存为流程，等待过程中继续复核账号、窗口和当前会话。图片及缺少链接的分享引用也必须重新取得精确 RuntimeId 控件，失效后不使用旧坐标；查看器或微信内置浏览器只清理本次已验证归属的窗口。已有链接走独立 Agent 浏览器，无需微信 UIA 关联。网页登录、验证码、访问限制或缺少正文时明确说明读取失败，不根据卡片标题猜内容。已物化路径缓存绑定到账号及原生消息身份。

## 诊断与开发验证

数据库只读诊断命令：

```powershell
D:\Miniconda\envs\cowagent-wechat\python.exe scripts\wechat_db_doctor.py --schema
D:\Miniconda\envs\cowagent-wechat\python.exe scripts\wechat_db_doctor.py --shadow-seconds 60
```

需要明确账号时追加 `--data-dir "数据目录" --account "账号目录名"`；`--cache-dir` 可指定缓存位置。`--shadow-seconds` 使用独立的 `validation/shadow-ledger.sqlite3` 落账，不进入 Agent 或发送流程；输出结构、计数、健康、稳定 ID、CPU/I/O 和耗时，不输出密钥或聊天正文。诊断账本仍可能包含聊天明文。

如需对比当前可见会话的 UIA 读取，可显式增加 `--benchmark-uia`。该项可能执行群发送者 OCR；一次历史查询耗时不代表持续接收的资源开销。

UIA 与会话控件诊断命令：

```powershell
D:\Miniconda\envs\cowagent-wechat\python.exe scripts\test_wechat_uia.py --standard-targets
D:\Miniconda\envs\cowagent-wechat\python.exe scripts\dump_wechat_conversation_tree.py --output .\tmp\wechat-conversations.json
```

控件树报告可能包含会话名称与消息预览。向外分享前去除真实聊天信息；只读诊断不需要实际发送参数。

开发回归使用合成加密库、临时 SQLite/WAL 和 UIA 替身：

```powershell
D:\Miniconda\envs\cowagent-wechat\python.exe -m pytest tests/wechat_desktop tests/test_wechat_desktop.py tests/test_wechat_desktop_robustness.py tests/test_baidu_ai_search.py -q
```

职责边界回归包括 `test_database_only_backend.py`、`test_db_passive_ui.py`、`test_db_reply_context.py`、`test_db_uia_attachment_bridge.py`、`test_uia_materializer.py` 和 `test_uia_passive_reads.py`：分别覆盖唯一数据库来源、被动接收、原生上文、附件关联拒绝、物化工作流与无前台操作的界面读取。

数据库状态重点查看 `db_read_healthy`、`db_read_stale`、`db_read_last_success_at`、`db_read_error_code`、`account_binding` 和各来源 `db_read_backlog`。数据库读取健康与 UIA 目标已验证是两个独立条件。

已有单机只读验证记录及性能数据见 [数据库后端说明](docs/wechat-db-backend.md)，这些数据属于当时的读取实现，并非本次移除 UIA 接收后的新实机结果。受控新入站消息、真实 WAL 追加逐条落账与无重复、附件底部证据及实际物化仍需实机验收；合成测试通过不能替代这一过程。
