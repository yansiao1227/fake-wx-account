# 更新日志

每次合并到主分支（`master` / `main`）前，在此目录新建或追加
`YYYY-MM-DD.md`，日期使用**北京时间的合并日**，同一天共用一个文件。
若跨日合并，将本次条目移到实际合并日的文件，保留其他改动的条目。

用几条精简中文列表描述用户可感知的变化；文档或维护改动也写明实际影响。
不粘贴提交记录、内部日志、测试输出或真实密钥。例如：

```markdown
# 2026-10-13

- 每天 18:00 向未被屏蔽的群发送当天更新说明。
- 补充更新日志的合并前检查步骤。
```

提交后，在仓库根目录检查本次改动：

```powershell
.\scripts\check_changelog.ps1 -BaseRef origin/master
```

合并到 `main` 时将基准改为 `origin/main`。检查读取已提交的变更，要求北京时间当日文件
新增有效列表项；仅有空文件、标题或未提交的改动不通过。主分支 PR 执行同样检查，
跨日待合并的 PR 需更新本次条目并重新检查。
要强制阻止未通过检查的合并，仓库维护者需在主分支保护中将 `Changelog check`
设为必需检查。
建议启用合并队列，让 `merge_group` 在实际合并前重新检查当天日期；
未启用队列时，跨日 PR 的旧成功结果不会自动失效，合并当天需更新条目并重跑检查。

## 每日群广播

微信桌面通道默认每天北京时间（UTC+8）18:00 检查当天文件，将非空内容发送给
数据库已知且当前不在 `auto_reply_group_blacklist` 中的群。遍历全部已知群，
不使用联系人查询的 50 条上限；广播无需 @，不受自动回复的 `group_reply_mode` 触发限制。
群名按首尾去空白、`casefold()` 后完整匹配黑名单，实际提交前再次检查发送权限和目标身份。

服务必须运行且微信已登录。暂停、停止或 `shadow_mode=True` 时禁止发送；
18:00 后启动或恢复会补跑当晚，往日不追补。读取时去除 Markdown 标题和 HTML 注释；
当天文件缺失，或去除后只有空白时不发送。
18:00 后补充内容会在当晚后续检查中处理尚未发送的群；已处理的群不再次广播。

每群每天至多一次，发送占位和结果持久化保存，避免重启重发；已提交但未确认、
结果不确定或发送失败时保留审计记录，不自动重发。发送额度不足且尚未提交时，
留待当晚后续周期继续。数据库已知群不一定在微信侧栏可定位，实际发送仍取决于
当前微信窗口、账号与目标校验结果。

所有设置仅放在 [channel/wechat_desktop/config.py](../channel/wechat_desktop/config.py)
的 `DEFAULT_CONFIG`，修改后重启进程：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `changelog_enabled` | `True` | 启用每日群广播 |
| `changelog_directory` | `"changelogs"` | 日志目录，相对路径从仓库根目录解析 |
| `changelog_send_hour` | `18` | 北京时间发送小时 |
| `changelog_send_minute` | `0` | 北京时间发送分钟 |
| `changelog_check_interval_seconds` | `30` | 调度检查间隔（秒） |
| `changelog_message_template` | `"今日更新（{date}）\n{content}"` | `{date}` 为当天日期，`{content}` 为日志内容 |
